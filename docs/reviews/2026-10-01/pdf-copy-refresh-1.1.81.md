### PDF 导出卡顿

旧路径在编辑器渲染进程同步执行全文 Markdown 解析、代码高亮、清理和 Mermaid 排版，还在打印期间占据全局文件写入队列。此前短样例测试不足以验证真实长文档。

新路径使用独立的、可销毁的打印 BrowserWindow：

- `dist/print.html` 接收原始全文快照，解析/清理/高亮/图表/排版均在独立打印渲染进程完成。
- 所有 PDF 导出显示进度弹窗：准备、选择位置、图片、解析、格式清理、图表实际完成数、排版、生成 PDF、安全写盘。
- Chromium 没有逐页生成进度 API，生成阶段显示不确定进度，不伪造逐页百分比。
- 支持取消、五分钟超时、打印渲染进程退出回收；退出应用或导出所属窗口销毁时取消任务。
- 文件队列只保护目标授权/身份固定及最终原子提交，不包住长耗时打印。
- 已有目标文件不提前截断；提交前重新验证 inode/dev/size/mtime，目标替换或并发变化会终止提交。
- 失败/取消只清理由本任务创建且身份未变的零字节占位，不删除其他程序替换的目标。
- 打印 IPC 仅允许登记过的打印窗口主框架访问自身任务；无 Node 集成，启用 sandbox/contextIsolation。
- 相对图片读取继续走已有文件授权边界；拒绝路径越界，并限制资源体积。
- 全文快照覆盖所有分片与当前未保存编辑。提示框、选中特效、编辑器气泡工具栏不进入打印页。

真实长文档验证：只读取用户之前指定的 OpenCode 架构文档，将副本写入隔离测试工作区；源文档未修改。58.6 万字节、161 个 Mermaid 图表，导出 295 页。专项首次约 146 秒、编辑器心跳最大间隔约 207ms；最终完整套件约 133 秒、最大间隔约 195ms。导出期间文件写入可完成，取消后既有目标文件保持原字节。

最终完整桌面套件的非打印性能回归：8 MiB 文档打开中位数约 297ms、输入约 72ms、最长主线程任务 60ms；350k 结构化 Markdown 打开约 236ms、输入约 82ms。分片加载、写盘和重载验证通过。

### 复制首尾空行

用真实 Windows `Control+C` / `Control+V` 复现：Electron 读回的 HTML 片段干净，但浏览器粘贴事件的 CF_HTML 包装会添加 `<html>/<body>` 以及 StartFragment/EndFragment 周围 CRLF。内部复制路径过早返回，绕过空白清理，包装换行被解析成 hardBreak，产生首尾空段。

- 内部复制分支先删除顶层、纯空白、含 CRLF 的包装文本节点。
- 纯文本行的闭合复制片段采用开放边界，避免在目标文本段两侧保留空壳段落。
- 剪贴板序列化优先处理普通段落的边界空壳，保留内部空行、媒体、代码块内部空白和格式语义。
- 增加真实双 MIME、原生快捷键及重复复制/粘贴验证，不只使用合成 DataTransfer。

### 上一轮编辑器三项失败

不是把失败测试放行，而是定位并修复：

1. 全选删除时多个旧源锚点映射到同一位置，Map 静默保留最后一个，旧内容错误留在磁盘。碰撞时放弃块级拼接，回退完整序列化；锚点一旦坍缩不再复活。
2. 键盘创建空行用例由同一个锚点碰撞问题导致。随上述修复恢复。
3. 图片对齐/缩放属性替换导致 NodeSelection 退化为 TextSelection，工具栏消失。提交属性时显式保留图片选择。
