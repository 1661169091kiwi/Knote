# v1.1.90：表格插入、选区工具栏与图片编辑性能

## 范围

1. 用户截图中的变窄和滚动条闪现位于「插入表格」菜单，而非已有表格的单元格宽度。尺寸网格现改为 body 下的固定定位独立面板，默认右开，空间不足左开；主菜单保留滚轮滚动但隐藏滚动条，不再因为网格展开改变内容宽度。
2. 文字格式工具栏使用可视窗口坐标，并与编辑区及滚动祖先的垂直可视范围相交；选区离屏时停靠边缘。更新仅由滚动、缩放和原有选区事件驱动，复用单帧合并机制，不引入轮询。格式按钮禁止自动滚回旧选区。
3. 相邻竖向缩放条仅给出设计建议，尚未改代码：侧栏保留中段短把手；编辑区用角点和边中把手；悬浮只强调当前控件，并分别提示「调整侧栏宽度」「调整编辑区大小」。需要用户确认后另行实施。
4. 用户确认缩放、对齐、裁剪都会卡顿，并批准本轮一并修复图片性能。

## 图片性能定位与修复

- 实际 Electron 编辑器、临时文档与临时用户配置；没有修改用户工作文档。
- 对照组：30 段正文/单图，500 个标题/单图；图片压力组为同一个 154,641 字节 PNG 的 61/241 次引用。241 次引用的原文件约 9.7KB，显示模型因图片 Base64 展开约 49.7MB。
- 原热路径是 Markdown 图片地址逐字符扫描，每个 Base64 字符均在 JavaScript 中进行分支与正则检查。改为由原生正则跳过普通字符串，只在转义、括号、空白处处理 Markdown 语义；不更换文件保存格式。
- 同一轮转换复用同一路径的显示地址，资源认证只扫描 URL fragment；纯 Markdown 图片不再重复进入 HTML 图片扫描。
- 裁剪保存会将内嵌图片持久化为本地资源。原比较逻辑将这种「相同字节的新显示地址」误判为外部全文变更，触发全文解析和节点重建。现仅在资源认证通过、载荷逐字相同、其余文档逐字不变且目标不歧义时按节点更新；真实文字或图片变化仍走正常同步。

## 同组复测

`scripts/image-edit-profile.mjs` 采集实际鼠标/键盘操作、dispatch/serialize/parse、长任务与 CPU profile。所有 GUI 运行于独立 Windows desktop，不切换用户桌面，不使用 taskkill/WMI。`KNOTE_IMAGE_PROFILE_ASSERT=1` 可断言图片编辑期间不发生全文解析。

| 241 次图片引用 | v1.1.89 点击/操作耗时 | 修复后耗时 |
| --- | ---: | ---: |
| 居中 | 830ms | 107ms |
| 连续两次缩放 | 1,657ms | 224ms |
| 靠右 | 840ms | 133ms |
| 确认裁剪 | 863ms | 201ms |

61 次引用修复后：居中 54ms、两次缩放 71ms、靠右 49ms、裁剪 107ms。

修复后四种场景、16 次操作均未触发全文解析；241 引用组最长单个长任务从约 815ms 降至 128ms。耗时是本机单轮数据，不是普遍保证；500 标题对照组未表现为本次图片热点，标题相关的其他性能问题不能据此排除。压力模型仍包含 Base64 字节，极大图片文档并未实现完全零阻塞。

基线日志：`image-lag-1.1.89-profile-full.log`；复测日志：`image-lag-1.1.90-profile-verified.log`（根目录日志被 Git 忽略）。
